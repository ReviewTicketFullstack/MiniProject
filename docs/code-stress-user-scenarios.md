# 유저 시나리오

## 공통 전제

- 대상은 Git 저장소다.
- 원본 저장소는 변경되지 않는다.
- 예측 모드: 저장소를 읽기만 한다.
- 구현 모드: 별도의 Worktree에서만 변경한다.
- 실험 결과는 병합 대상이 아니라 관측 대상이다.
- Worktree의 코드 변경분은 실험 종료 후 폐기되고, 측정 결과와 증거만 남는다.
- 모든 비용 지표는 정적 분석 또는 실제 변경 결과를 기반으로 측정한다.ㅍ

<br>

## Possible examples

**예시1**
기존 UI에 버튼 또는 컴포넌트 추가
기존 화면에 알림 기능 추가
기존 API 응답에 간단한 UI 표시 추가
기존 기능에 작은 옵션 추가

목표 : 작은 기능 추가에 필요한 변경 범위와 구현 비용을 착수 전에 확인

**예시2**
새로운 도메인 추가
예: Payment 도메인 추가
예: Notification 도메인 추가
하나의 기존 도메인을 여러 도메인으로 분리
새로운 기능을 위해 여러 계층에 걸친 구조 변경
새로운 도메인과 관련된 UI/API/상태 관리 코드 추가

목표 : 중대 규모 기능 추가 또는 도메인 구조 변경 전에 예상되는 변경 비용과 실제 구현 비용을 확인

**예시3**
백엔드의 에러 메시지에 대한 의존성을 제거하고 프론트엔드가 에러코드를 사용자 메시지로 변환하도록 변경

목표 : 기존 기능의 책임이나 데이터 흐름을 변경하면서 예상되는 영향 범위를 확인

<br>

| 항목       | 내용                                    |
| ---------- | --------------------------------------- |
| **Actor**  | 착수 전에 변경 규모를 가늠하려는 개발자 |
| **트리거** | `/change-drill` 실행                    |

<br>

**흐름**

1. 저장소 경로를 묻는다 (기본: 현재 디렉터리).
2. **"어떤 변경을 예측할까요?"** — 자연어로 자유롭게 입력한다. ✅
3. 어시스턴트가 임시 시나리오(id/name/description/prompt)를 만들어 확인받는다.
4. `--predict`로 저장소를 검증한다. Worktree는 만들지 않는다.
5. 읽기 전용 Agent 2개가 병렬로 코드를 분석하고 각자 예측 JSON을 저장한다.
6. `--predict-report`가 두 예측을 집계해 터미널 리포트를 출력한다.
7. `git status`로 저장소가 그대로인지 확인한다.

**출력** — 고정된 순서의 터미널 리포트:
KEY METRICS(토큰/파일 수/LOC/복잡도, Agent A·B 나란히) → 막대 그래프 →
CONSENSUS(합치도) → DIFFERENCE(차이) → 추정치 고지.

> 모든 수치는 **정적 분석 기반 추정치**다. 실측값이 아니며 실제 구현 비용을 보장하지 않는다.
> 상세 관찰(구현 접근, 결합도, 중복, 책임, 변경용이성)은 터미널에 표시되지 않고 JSON에만 남는다.

## S2. 결과 확인

**출력물**

| 모드        | 산출물                                                                          |
| ----------- | ------------------------------------------------------------------------------- |
| 예측        | `results/agent_A/prediction_<id>.json` + `results/agent_B/prediction_<id>.json` |
| 예측 리포트 | 터미널 리포트                                                                   |
| 구현        | `results/<id>_<ts>.json`                                                        |
| 구현 상세   | `results/<id>_<ts>.md`                                                          |
| 변경 증거   | `results/<id>_<ts>.diff`                                                        |

<br>

**터미널 레포트**

```
KEY METRICS
Token / Files / LOC / Complexity
Agent A | Agent B

BAR GRAPH

CONSENSUS
Agent 간 예측 합치도

DIFFERENCE
예측 간 주요 차이

ACTUAL
실제 변경 결과

ESTIMATION ERROR
예측값과 실제값의 차이
```
