# Minutely 기획서

## 1. 배경 · 목적

C조_한컴 프로젝트의 기획·자료는 Notion **C조_한컴** 페이지에서 관리된다. 팀원이 페이지를
계속 수정하는데, **무엇이 바뀌었는지**를 사람이 매번 눈으로 훑어 옮기는 일이 번거롭다.
또 회의 내용을 회의록으로 옮기는 것도 수작업이다.

**목표**: Claude Code 플러그인 `minutely`로 두 가지를 자동화한다.
- (A) C조_한컴의 변화를 감지해 **"노션 변경 내용 정리 (Claude 전용)"** 페이지에 날짜별 로그로 정리.
- (B) 회의 **녹음/텍스트 파일**을 전사·요약해 **회의록 DB**에 새 회의록으로 작성.

두 경로 모두 **초안을 먼저 보여주고 사용자가 승인해야만** Notion에 쓴다.

## 2. 핵심 기능

| 경로 | 트리거 | 입력 | 출력 |
|---|---|---|---|
| A | `/minutely`, "노션 정리" | C조_한컴 (소스 DB 5개 + 페이지 산문) | "노션 변경 내용 정리 (Claude 전용)" 페이지에 append |
| B | `/minutely meeting <파일>` | 녹음/영상 또는 `.txt`/`.md` | 회의록 DB 새 행 |

## 3. 설계 결정 (인터뷰 결과)

| 항목 | 결정 |
|---|---|
| 산출물 | Claude Code 플러그인 |
| Notion 접근 | Notion MCP 커넥터 (native tool) |
| 감시 범위 | C조_한컴 페이지 전체(소스 DB + 산문), 출력 대상은 제외 |
| 변화 기준 | 로컬 스냅샷 diff (소스 DB) + 페이지 dump diff (산문) |
| 실행 | 수동 슬래시 커맨드 (스케줄 확장 여지) |
| 변경 정리 출력 | "노션 변경 내용 정리 (Claude 전용)" 페이지에 날짜 로그 append |
| 회의록 작성 | 회의 녹음/텍스트 파일 → 회의록 DB 새 행 |
| 쓰기 방식 | 초안 확인 후에만 write |
| 상태 저장 | 프로젝트 `.minutely/` (git 제외) |
| 음성 전사 | Gemini(우선) 또는 OpenAI Whisper API (ffmpeg 추출) |
| 로그 내용 | **노션 실제 변경 내용만 요약. Claude 의견·제안은 넣지 않음** |

## 4. Notion 대상 구조 (실측)

- 감시 페이지 `C조_한컴` `3aabdeac-d0b4-804d-a1c2-dfc339401282` — 산문 + 임베드 DB 7개.
- **소스 DB 5개** (감시): 제출자료·일정·마일스톤·스터디자료·프로젝트안내.
- **출력**: (A) Claude 전용 페이지 `3abbdeac-d0b4-802e-be23-f0a4c4f131e0`,
  (B) 회의록 DB `collection://c5bbdeac-d0b4-8333-bba6-07d1ccebfcfb` (회의명·날짜·내용·상태).
- **diff 제외** (피드백 루프 방지): 회의록·데일리 스크럼 DB.

> ⚠️ 피드백 루프: 회의록/데일리는 C조_한컴 하위라, 자동 생성물이 다음 실행에서 "변화"로
> 잡히면 안 된다. 그래서 diff 대상에서 제외한다.

## 5. 아키텍처

```
경로 A: 수집(query-data-sources + fetch) → 정규화(current.json / page_new.txt)
        → diff(snapshot.py + pagediff.py) → 요약 → 초안 → 승인 → 페이지 append → 스냅샷 갱신
경로 B: 파일 → (오디오면 transcribe.py=ffmpeg+Gemini/Whisper / 텍스트면 직접 읽기)
        → 회의록 양식 요약 → 초안 → 승인 → 회의록 DB 새 행
```

- `snapshot.py` — 소스 DB 행 정규화 스냅샷 저장·비교(added/modified/removed). 유닛테스트 8개.
- `pagediff.py` — 페이지 산문 dump를 difflib로 비교해 바뀐 구간 추출.
- `transcribe.py` — ffmpeg로 오디오 추출 → Gemini(있으면 우선) 또는 OpenAI Whisper 전사 (표준 라이브러리, 청킹·재시도).
- `config.py` — Notion id 상수 + `OPENAI_API_KEY`/`GEMINI_API_KEY` 로드.

## 6. 한계 · 미해결

- **"누가" 추적 불가**: 이 Notion MCP는 `last_edited_by`/편집자·수정시각을 노출하지 않음.
  표준 API도 잘해야 페이지 "마지막 편집자 1명"뿐(필드별·이력 아님), 전체 감사 로그는 Enterprise 전용.
  → per-change "누가 뭐 바꿈"은 제공 불가. (담당자/작성자 person 속성이 있는 DB만 부분 근사 가능.)
- **산문 baseline 필요**: 산문 변화를 잡으려면 이전 페이지 dump가 있어야 함(`.minutely/page.txt`).
- **대용량 페이지**: C조_한컴은 약 54KB라 한 번에 fetch 시 컨텍스트 초과 → 나눠 수집 + dump 비교.

## 7. 향후 확장

- 스케줄 자동 실행(cron).
- 로그에 "Claude 제안" 섹션 옵션(노션 변경 내용과 시각적으로 분리, 기본 꺼짐).
- 담당자 person 속성 표기(부분적 who 근사).
