# Minutely 스킬·스크립트 상세

minutely 플러그인의 스킬(`minutely`) 하나가 전체 절차를 어떻게 지휘하는지, 그리고 각 스크립트가
무슨 역할을 하는지 설명한다.

---

## 1. 스킬이 어떻게 "지휘"하나

`skills/minutely/SKILL.md`는 **실행 코드가 아니라 지시서(instructions)** 다. 동작 방식:

1. 사용자가 트리거(자연어 또는 `/minutely`)를 입력하면 스킬이 **Claude의 컨텍스트로 로드**된다.
2. Claude는 SKILL.md에 적힌 절차를 **위에서 아래로 읽으며**, 각 단계에서 필요한
   **Notion MCP 도구**나 **로컬 Python 스크립트**를 직접 호출한다.
3. 인자에 따라 **경로 A**(노션 변화 정리) 또는 **경로 B**(회의록 작성)로 갈라진다.

즉 "지휘자"는 스킬 문서, "연주자"는 Claude이며, 실제 계산(diff, 전사)은 스크립트가, Notion
읽기·쓰기는 MCP 도구가 담당한다. 스킬은 **무엇을 어떤 순서로** 할지 정한다.

**스킬이 호출하는 Notion MCP 도구 (4종)**
| 도구 | 용도 |
|---|---|
| `notion-query-data-sources` | 소스 DB 행 조회(SQL), 중복 확인 |
| `notion-fetch` | 페이지 산문/커넥터 상태(`id:"self"`) 조회 |
| `notion-update-page` | Claude 전용 페이지에 로그 append |
| `notion-create-pages` | 회의록 DB에 새 행 생성 |

---

## 2. 트리거 & 경로 분기

| 입력 | 경로 | 결과 |
|---|---|---|
| `/minutely`, "노션 정리", "노션 변경 정리해줘" | **A** | C조_한컴 변화 → "노션 변경 내용 정리 (Claude 전용)" 페이지에 로그 append |
| `/minutely meeting <파일>`, "이 녹음 회의록으로", "회의록 작성" | **B** | 파일 전사·요약 → 회의록 DB 새 행 |

고정 대상 id는 `config.py`와 SKILL.md에 동일하게 박혀 있다(감시 페이지, Claude 전용 페이지,
회의록 DB, 소스 DB 5개, diff 제외 DB 2개).

## 3. 경로 A — 노션 변화 → Claude 전용 페이지

| 단계 | 하는 일 | 호출 | 입력 → 출력 |
|---|---|---|---|
| **A1 수집** | 소스 DB 5개 행 + 페이지 산문 수집·정규화 | `notion-query-data-sources`, `notion-fetch` | Notion → `.minutely/current.json`, `.minutely/page_new.txt` |
| **A2 diff** | 이전 대비 변경 추출 | `snapshot.py diff`, `pagediff.py` | 스냅샷 vs 현재 → added/modified/removed + 산문 `[+]/[-]` |
| **A3 요약** | 의미 있는 변경만 정리(노이즈 제거, 미결정 강조) | Claude | diff → 요약 |
| **A4 초안** | 로그 블록을 채팅에 먼저 표시 | Claude | 요약 → 초안 |
| **A5 쓰기** | 승인 시에만 페이지 끝에 append | `notion-update-page` (`insert_content`, `position:end`) | 초안 → Claude 전용 페이지 |
| **A6 갱신** | 이번 수집분을 다음 기준선으로 승격 | `snapshot.py promote` + `page_new.txt→page.txt` | current → snapshot |

**예외 처리**
- **최초 실행**(`snapshot.py`가 `baseline:true` 또는 `pagediff.py`가 `BASELINE_MISSING`):
  비교 대상 없음 → A6 promote만 하고 "기준선 생성" 보고 후 종료.
- **무변경**(diff 빈 배열 + `NO_PROSE_CHANGE`): 보고 후 종료.

`.minutely/current.json` 형식:
```json
{"page_id":"3aab…","captured_at":"<ISO>",
 "items":{"<행 id>":{"kind":"row","source":"<DB 이름>","title":"...","text":"..."}}}
```

A2에서 실제로 도는 명령:
```bash
python "$CLAUDE_PLUGIN_ROOT/skills/minutely/scripts/snapshot.py" diff --current .minutely/current.json
python "$CLAUDE_PLUGIN_ROOT/skills/minutely/scripts/pagediff.py" --old .minutely/page.txt --new .minutely/page_new.txt
```

## 4. 경로 B — 회의 파일 → 회의록 DB

| 단계 | 하는 일 | 호출 | 입력 → 출력 |
|---|---|---|---|
| **B1 텍스트화** | 오디오/영상이면 전사, 텍스트면 그대로 읽기 | `transcribe.py` (오디오만) | 파일 → 전사문/텍스트 |
| **B2 요약** | 회의록 양식으로 요약(기존 회의록 문체 참고) | Claude | 텍스트 → 회의명·날짜·내용·상태 초안 |
| **B3 쓰기** | 승인 시에만 새 행 생성(중복 확인) | `notion-create-pages`, `notion-query-data-sources` | 초안 → 회의록 DB 새 행 |

- 확장자 판단: `.m4a .mp3 .wav .mp4 …` → `transcribe.py`, `.txt .md` → 직접 읽기.
- 키/ffmpeg 없으면 `transcribe.py`가 안내 메시지 출력 후 종료 → Claude가 사용자에게 전달.

B1 명령:
```bash
python "$CLAUDE_PLUGIN_ROOT/skills/minutely/scripts/transcribe.py" "<파일경로>"
```

## 5. 스크립트별 역할

| 파일 | 역할 | 인터페이스 | 의존성 |
|---|---|---|---|
| `snapshot.py` | 소스 DB 행 스냅샷 저장·비교 | CLI `diff` / `promote` (`--current`, `--baseline`), 함수 `diff_items()` | 표준 라이브러리 |
| `pagediff.py` | 페이지 산문 dump 비교 | CLI `--old --new`, 함수 `diff_text()` | 표준 라이브러리(`difflib`) |
| `transcribe.py` | 오디오 → 전사 | CLI `transcribe.py <파일>` | ffmpeg/ffprobe, Gemini/OpenAI Whisper, `config.py` |
| `config.py` | id 상수 + 키 로드 | 상수 + `load_openai_key()`/`load_gemini_key()` | 표준 라이브러리 |
| `tests/test_snapshot.py` | diff 유닛테스트 8개 | `python tests/test_snapshot.py` | `unittest` |

### snapshot.py
- **정규화 입력**(`current.json`)의 `items`(행 id → {kind, source, title, text})를 직전 스냅샷과 비교.
- `diff` — `snapshot.json` 없으면 `{"baseline":true, …}` 출력(최초 실행). 있으면
  `added`/`modified`(before/after)/`removed` + `changed` 플래그 출력.
- `promote` — `current.json`을 `snapshot.json`으로 복사(다음 기준선).
- 공백만 다른 변경은 `_norm()`으로 무시(오탐 방지). `title`·`text` 변화만 modified로 잡음.

### pagediff.py
- 큰 산문 페이지는 DB 행 스냅샷으로 못 잡으므로, 이전/현재 **dump 텍스트**를 `difflib.SequenceMatcher`로 비교.
- `[-]`(삭제)·`[+]`(추가) 구간을 사람이 읽을 형태로 출력.
- `MIN_CHUNK`(=4) 미만 조각은 표 태그 재정렬 같은 노이즈로 보고 버림.
- 상태 신호: 기준선 없으면 `BASELINE_MISSING`, 변화 없으면 `NO_PROSE_CHANGE`.

### transcribe.py
- `ffmpeg`로 mono 16kHz mp3 추출 → `GEMINI_API_KEY` 있으면 Gemini(`gemini-flash-latest`),
  없으면 OpenAI Whisper(`whisper-1`) 업로드 → 전사 텍스트를 표준출력.
- 25MB 한도 초과 시 시간 균등 **청킹** 후 이어붙임. HTTP 429/네트워크 오류 **재시도** 내장.
- 멀티파트 업로드(OpenAI)·JSON 요청(Gemini)을 손으로 조립 — 외부 pip 패키지 불필요(표준 라이브러리만).
- Gemini 요청은 mp3를 `audio/mp3` mime으로 고정(`audio/mpeg`로 보내면 오디오가 무시됨).
- 키는 `config.load_gemini_key()`/`load_openai_key()`가 환경변수 → `./.env` → `~/.config/minutely/.env` 순으로 로드.

### config.py
- id 상수: `WATCH_PAGE_ID`, `CHANGE_LOG_PAGE_ID`, `MEETING_MINUTES_COLLECTION`,
  `SOURCE_COLLECTIONS`(5), `EXCLUDED_COLLECTIONS`(회의록·데일리, diff 제외).
- `load_openai_key()`/`load_gemini_key()` — 위 순서로 각각 `OPENAI_API_KEY`/`GEMINI_API_KEY` 탐색.

## 6. 상태 파일 & 데이터 흐름

프로젝트 루트 `.minutely/` (전부 git 제외):

| 파일 | 역할 |
|---|---|
| `snapshot.json` | 마지막으로 본 소스 DB 정규화 콘텐츠 (DB 기준선) |
| `page.txt` | 마지막으로 본 페이지 산문 dump (산문 기준선) |
| `current.json` | 이번 실행 소스 DB 수집분 |
| `page_new.txt` | 이번 실행 페이지 산문 dump |

흐름(경로 A):
```
수집 → current.json / page_new.txt
        │
        ├─ snapshot.py diff  (current.json  vs  snapshot.json)
        └─ pagediff.py       (page_new.txt  vs  page.txt)
        │
     [변경 있음 + 승인]
        │
     promote:  current.json → snapshot.json,  page_new.txt → page.txt   (다음 기준선)
```

## 7. 안전 원칙 (SKILL.md 명시)

- **승인 없이는 Notion에 쓰지 않는다** — 항상 초안 → 확인 → 쓰기.
- **출력 DB는 diff에서 제외** — 회의록·데일리 스크럼은 C조_한컴 하위지만 자동 생성물이
  다음 실행에서 "변화"로 잡히는 **피드백 루프**를 막기 위해 감시하지 않는다.
- **지어내지 않는다** — 로그·회의록엔 노션에 실제로 있는 내용만. 모르면 비우거나 물어본다.
